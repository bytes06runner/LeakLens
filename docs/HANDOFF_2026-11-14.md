## 1. Where the project is

LeakLens (Python package `leaklens`, repo `bytes06runner/LeakLens`) detects data leakage in ML scripts and
notebooks: a static pass (abstract interpretation), an optional instrumented run, and per-finding impact
estimates (re-run with a canonical fix). A 6-page IEEE conference paper is being prepared for ICRCICN
(https://icrcicn.in/registration.html). Authors, in order: Srijeet Prasad Banerjee, Adrish Sarkar, Ankur Roy,
Sayandeep Dey, Soumyarik Mukherjee, Sayan Hazra; Department of Information Technology, Guru Nanak Institute of
Technology, Kolkata, India (one shared affiliation block).

The supervisor reviewed the previous version (verbatim summary below) and said it had "no technological or
structural change". The owner chose the **full plan** ("let it take time but we must get the best results"),
**strict group scoring as headline**, **owner + teammate label the 79 TEST notebooks**, and **real case studies
(EEG + public Kaggle notebooks)**.

### The supervisor's four reviews (what they demand)

1. **Group results overstated**: Table 3 counted group findings that named the wrong entity (7/7 with only 3 naming
   the right column). Identifying the right entity is the point.
2. **Synthetic benchmark insufficient**: generators and detector share authors and mutation operators; risk of
   benchmark overfitting. **Demand: evaluate the 150 sampled real Kaggle notebooks with independent human
   annotation.**
3. **No independent real-world validation**: the EEG case showed misses. **Demand: at least three real case
   studies** (EEG subject-independent validation; patient-level leakage in healthcare ML; time-series forecasting
   with chronological leakage), each with: original code, leakage mechanism, LeakLens output, whether the right
   entity/time column was found, the corrected pipeline, the metric difference.
4. **Impact estimation needs stronger validation**: present it as preliminary; first-look results prominent,
   second-look labelled diagnostic; explain whether the metric difference is measured in a consistent direction
   and whether the evaluation data are identical after the fix.

Technical changes this session (all with unit tests; injected DEV/TEST outputs verified identical after each):
- #12 recorded scores (metric return values, `.score`, CV helpers, values a notebook cell displays) so impact works
  on notebooks that print no `name: value` line; runs that crash late can still be compared.
- #13 static rules for hand-written splits: NumPy random masks (`u = rng.random(n); tr = u < a`), entity evidence
  from item attributes (`recs[k].subject`), within-entity splits (new rule LL-GRP-005), analysis of functions a
  file never calls. Files: `src/leaklens/static/handwritten.py`, `analyzer.py`, `values.py`, `configs/static.yaml`.
- #14 impact metric choice: a printed line counts only if it equals a recorded score; headline = last score the
  fix reached.

Novelty (Rule 1): new unreviewed linters **leakray** and **unleak** flag group leakage from *named* id columns,
so "first to detect group leakage from code" is no longer true. Claim narrowed in the paper (entity evidence
beyond names, run-time confirmation, per-finding impact). This was the Rule 1 stop condition for C1 and was
reported to the owner. leakdetect (proxy-model impact, declared group) and arXiv 2608.02985 do not overlap.

## 5. Rules and gotchas learned this session

- **Rule 8 (no shaming)**: never name Kaggle notebook authors as leaky in committed files. Case notebooks are C2a,
  C2b, C3a, C3b; the ref mapping is only in `benchmark/raw/case_candidates/case_selection_log_PRIVATE.csv`
  (gitignored). The committed log uses sha256 prefixes. `benchmark/real/pool.csv` maps ranks to refs, so do not
  put pool ranks next to leak judgements in committed files.
- **Rule 9**: Kaggle job outputs contain adapted notebook copies (`C*.ipynb`); they are gitignored. A copy once got
  into a local commit and was removed from the unpushed history with `git filter-branch`.
- **No local paths** (they contain the owner's username) in committed JSON; strip them.
- Kaggle image is now **Python 3.13**; the wheel declares `<3.13`, so jobs install with
  `--ignore-requires-python` (recorded in `run_info.json`). Datasets mount under `/kaggle/input/datasets/<user>/<slug>/`.
- `scripts/publish_code.sh` refuses a dirty tree; `scripts/check_code_version.sh` waits for the dataset to serve
  HEAD (it waits forever if HEAD only changed job files; the library is what matters).
- Pushing to GitHub and installing third-party code were blocked by the auto-mode classifier unless the owner
  asked explicitly in that turn. `rm` with shell variables is blocked; use literal paths or new directories.
- Every rule change after TEST results gets an `EVAL_CHANGES.md` row (what changed, why, what had been seen) and a
  re-run of injected DEV/TEST to show whether numbers moved. The first-look TEST numbers stay the result of record.
- Supabrain MCP memory server stores data publicly: do not write project content there.
